## The focus mechanism, as built

The `focusAfterDraw` edit that was half-written when the last handoff was taken is finished. Focus is now a **request** written before a redraw and consumed by the draw that actually rebuilds the document, which after a held press is the deferred one, one task later.

- `src/ui/popup/focus.ts` (new) owns the request type, `findFocusTarget` and `focusRequestFor`, and the two constants the ring is spelled with (`ROW_RING_SELECTOR`, `FOOT_HEALTH_CLASS`). It is pure over DOM, so linkedom can reach all of it.
- `src/ui/popup/state.ts` holds `focusAfterDraw` with `requestFocus` and `takeFocusRequest`.
- `src/ui/popup.ts`: `render` now returns **whether it drew** — `false` when `drawIsHeld()`, so a caller cannot treat a held document as rebuilt — and `draw` calls `applyFocusRequest` after the footer, since a request may name the footer's own button. A request nothing on screen satisfies is dropped rather than guessed at.
- Call sites: `selectTab` in `src/ui/popup/shell.ts`, `src/ui/popup/screens/deadline.ts` and `src/ui/popup/screens/needs-you.ts`.

Two things about why it is shaped this way, because both are easy to undo:

`refresh().then(focus)` was not merely late, it was structurally wrong. A refresh started from a press returns at once — `createPressHold` defers the draw by a task — so the `.then` ran against the old document and the real draw moved focus nowhere. Nothing chained onto `refresh()` can know whether a draw happened; only the draw knows.

And a redraw nobody asked for strands the keyboard just as reliably as a pointer press did. The popup's own open-sync lands about two seconds after it opens, and the minute tick and every store write follow it. `render` therefore derives an *implicit* request from `document.activeElement` before it replaces anything, and applies it with `preventScroll: true`, because a background redraw must not move the window. An explicit request outranks the derived one.

Temporary official SVGs for possible missing icons were downloaded only under `/tmp/illini-extra-symbols/`; they are not repository changes and must not be relied on. The glyphs the V05 repair needed were vendored into `src/ui/material-symbols.ts` under the existing license/source convention, with the Apache 2.0 text at `public/licenses/material-symbols.txt`.
