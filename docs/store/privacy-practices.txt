------------------------------------------------------------------- [1 of 10] --
SINGLE PURPOSE DESCRIPTION
-------------------------------------------------------------------------------
Illini Dash shows a University of Illinois student their own assignment and exam
deadlines from the course sites they already use, gathered onto one calendar,
with reminders before each one is due.

That is its only function. It reads deadline pages using the login sessions
already present in the browser, extracts the due dates, and displays them. Every
permission requested exists to do that and nothing else: to read those pages, to
keep the result on the user's own device, and to remind them in time.

It modifies nothing on the sites it reads. The one content script, on
Campuswire, is registered only if the user switches Campuswire on, reads posts
already on screen, and changes nothing. Optionally, and only if the user
connects it, deadlines are copied to a calendar it creates in the user's own
Google account. It has no account, no server and no second feature.

------------------------------------------------------------------- [2 of 10] --
"storage" JUSTIFICATION
-------------------------------------------------------------------------------
Stores the deadlines that have been read, the course names they belong to, and
the user's own settings and corrections — which sources are switched on, which
courses are hidden, entries they have merged or split, and items they have
marked done.

Without it the extension would have to re-fetch every source each time the popup
is opened, which would be slow and would hit the course sites far more often
than necessary. Instead the calendar is on screen instantly and survives a
browser restart.

Everything is written to chrome.storage.local on the user's own device. Nothing
is synced between devices and nothing is transmitted. Uninstalling the extension
deletes all of it.

------------------------------------------------------------------- [3 of 10] --
"alarms" JUSTIFICATION
-------------------------------------------------------------------------------
Two things must happen on a schedule, and a Manifest V3 service worker is torn
down when idle and cannot stay resident to do either.

First, checking the sources for new, changed or removed deadlines — every 30
minutes by default, adjustable by the user between 15 and 120 minutes.

Second, firing each reminder at the moment it is due: 24 hours and 2 hours
before a deadline, and once a day for an exam that is open for booking but not
yet reserved.

chrome.alarms is the only supported way to wake a service worker at a set time,
so it is required for both.

------------------------------------------------------------------- [4 of 10] --
"notifications" JUSTIFICATION
-------------------------------------------------------------------------------
Shows the deadline reminders, which are one of the main reasons a user installs
this extension.

A notification appears 24 hours and 2 hours before an assignment or exam is due,
naming the course, the item and when it is due. A separate daily reminder covers
exams that are open for booking at the campus testing centre but have not been
reserved yet, because that deadline is otherwise invisible.

Quiet hours are respected, so nothing fires overnight. Both lead times and quiet
hours are configurable, and reminders can be switched off entirely in Settings.

Notifications are only ever about the user's own deadlines. There is no
promotional, marketing or other unsolicited notification of any kind.

------------------------------------------------------------------- [5 of 10] --
"offscreen" JUSTIFICATION
-------------------------------------------------------------------------------
The deadline data lives inside HTML pages and must be parsed, and a Manifest V3
service worker has no DOM parser available to it.

Fetched pages are parsed in an offscreen document using the browser's own inert
HTML parser — the document parses markup into elements and reads text out of
them; it runs no scripts and loads no subresources. This is the documented
DOM_PARSER reason for the offscreen API and is the intended use of it.

The offscreen document is created for this and nothing else. It stores no data,
holds nothing between calls, and is not used for audio, clipboard, scraping or
any other purpose.

------------------------------------------------------------------- [6 of 10] --
"contextMenus" JUSTIFICATION
-------------------------------------------------------------------------------
Adds exactly one right-click menu item: "Report this page to Illini Dash".

If a course page's deadlines are not being read correctly, the user right-clicks
that page and chooses it. This opens the extension's own settings page with the
address filled in, where the user can then choose to prepare a report.

Nothing is fetched or sent as a result of the click itself, and nothing is
uploaded at any point: the report is assembled locally, identifying details are
removed, and the user is handed a file that they alone decide what to do with.

This is the only context menu item the extension adds, and it appears only on
the course sites the extension supports.

------------------------------------------------------------------- [7 of 10] --
"scripting" JUSTIFICATION
-------------------------------------------------------------------------------
Registers exactly one content script, on https://campuswire.com/* and nowhere
else, and only after the user switches Campuswire on in the extension's
settings and Chrome grants that host. Nothing is registered on install.

Campuswire's class feed is drawn by JavaScript: the server returns an empty
shell and the posts arrive over a token-authenticated API, so there is no page
to fetch. Reading the posts the browser has already rendered for the user is
the only way to find the deadlines instructors state in them.

The script reads the feed's own markup - post titles, bodies, numbers, dates
and the class name - and hands what it finds to the extension. It makes no
request to Campuswire, reads no cookie, token, localStorage or other page, and
modifies nothing. Switching Campuswire off, or revoking the host, unregisters
it immediately.

------------------------------------------------------------------- [8 of 10] --
HOST PERMISSION JUSTIFICATION
-------------------------------------------------------------------------------
Reads the user's own assignment and exam pages with the browser's session:
canvas.illinois.edu (courses, planner), www.gradescope.com (assignments),
us.prairielearn.com (assessments), us.prairietest.com (exams),
smart.physics.illinois.edu (PHYS 211-214). raw.githubusercontent.com: a daily
public JSON list of supported course sites, no cookies, nothing about the user.

These six are up front: a background schedule has no gesture to request a
permission from. It reads only pages the account can already see, at most every
15 minutes, parses them locally, and never signs in or writes to a site.

Optional hosts: nothing at install. Many UIUC course sites are on their own
domains (cs124.org), so the host is unknown in advance. One is requested at
runtime, per site, read-only, when the user switches that course on; Chrome
names it, and no entry may name a host granted above. Same for campuswire.com,
from the Campuswire switch, and www.googleapis.com, from Connect under Google
Calendar.

------------------------------------------------------------------- [9 of 10] --
"identity" JUSTIFICATION
-------------------------------------------------------------------------------
Used only by the optional Google Calendar sync, which is off on install and
starts only when the user presses Connect in the extension's settings.

It obtains an OAuth token for exactly one scope:
https://www.googleapis.com/auth/calendar.app.created

That scope lets an app create a secondary calendar and read or write only the
calendars it created itself. It grants no access to any other calendar: the
extension cannot list, read, change or delete the user's existing calendars or
events, and Google enforces that.

With it, the extension creates one calendar named "Illini Dash" and writes the
user's own deadlines to it - course, title, due time, submission link. Finished
and hidden deadlines are removed from it. Pressing Disconnect deletes those
events and the calendar, and clears the token.

Chrome holds the grant; the extension stores no token and never sees a Google
password. No data reaches the developer: events go from the user's browser to
the user's own Google account.

------------------------------------------------------------------ [10 of 10] --
REMOTE CODE
-------------------------------------------------------------------------------
Answer: "No, I am not using Remote code."

(Not a field — background if a reviewer asks. The daily fetch from
raw.githubusercontent.com returns DATA, not code: a JSON list of CSS selectors,
a date format, a timezone and a filter pattern per supported course site. It is
interpreted by a runner that ships inside the package. The extension contains no
eval(), no new Function(), no remotely-loaded <script>, and no externally
referenced modules. All executable code is in the uploaded zip.)

An earlier version of this file said to check nothing, on the reading that the
form asks what you *collect* and that nothing is transmitted off the device.
That reading is wrong, and Google's User Data FAQ says so directly:

  "Extensions are required to disclose how they handle user data, even when
   data is processed or stored locally on a user's device and is not
   transmitted to external servers or third parties."

  "Generally, by 'handle' we mean collecting, transmitting, using, or sharing
   user data."

Local-only is not exempt, so "Website content" applies: assignment titles,
course names, due dates and links are read out of pages and kept in
chrome.storage.local.

WHY THE OTHERS STAY UNCHECKED

Authentication information - the extension never reads a password or a cookie.
It issues requests and the browser attaches the session itself.

Personally identifiable information - nothing identifying is stored. The
broken-page report asks for a NetID and a name in order to REMOVE them from the
file; both are held in memory for that one operation and never written to
storage. Verified against the code: no write path exists for either.

Web history - a judgment call, and the one worth reading twice before you
certify. The extension keeps no list of visited pages: no URLs, no page titles,
no per-page record. It keeps one integer per source - the last time a page
finished loading on a site it already has permission to read - in session
storage, cleared when the browser closes, used only to decide whether the last
fetch is out of date. That is not "the list of web pages a user has visited".
If a reviewer disagrees, this is the box they will name, and the honest response
is to check it rather than argue.

User activity - no clicks, keystrokes, mouse position, scroll or network
monitoring of any kind.

CERTIFY ALL THREE

No selling or transferring to third parties: true. The only transfer of any
kind is the optional Google Calendar sync, and that sends the user's own
deadlines to the user's own Google account at their request - not to a third
party and never to the developer.
Nothing unrelated to the single purpose: true.
No creditworthiness or lending use: true.
